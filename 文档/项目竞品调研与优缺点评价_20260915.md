# 刷题记（site/）竞品调研与优缺点评价

> 调研日期：2026-09-15 · 对象：本项目 `site/`（个人医学刷题 PWA）
> 结论先行：**不是一个"小一号的医考帮"，而是一个"带题库的 Anki 替代品 + 校内考核特化层"**。跟商业 App 比题量没有意义（差 200 倍），真正的对标是 Anki（记忆算法）和极光题库本体（同源同题）。

## 三、优势（真实的、可验证的）

### A1. 题源精准命中校内考核 —— 商业 App 的结构性盲区
扩展组 9,979 题来自 `ykb_` / `school_` / `kaoyan_` 源站，覆盖的是**南医大自命题口径**。医考帮/蓝基因/阿虎全部面向执医·考研·职称，题库再大也不覆盖你的期末卷。这是花钱买不到的差异，**也是本项目唯一不可替代的价值点**。

### A2. 解析覆盖率 98.7% + 结构化，压过所有商业 App
医考帮解析"偏精简"、阿虎 89% 有文字解析。本项目 14,693/14,881 = **98.7%**，且是结构化 blocks（`bf` 题干要点 / `an` 解析 / `ab` 选项辨析 / `pf` 考点 / `cn` 结论 / `tx` 原文），带章节小节补全。解析质量是刷题工具的第二护城河，这一项你赢。

### A3. 完全离线、零成本、数据自有
PWA + SW + 分片懒加载，27 MB 数据不阻塞首屏。无广告、无付费墙、无账号体系绑架。商业 App 的每一个功能（错题本、组卷、离线包）都可能在下一次改版进付费墙——你的不会，因为数据在硬盘上。

### A4. 工程化水平对同类自建是降维打击
13 个 verify 脚本、id 别名网 66,699 条、`release.mjs` 一键链、`dist_parity` 逐文件 md5、**失败即 exit 1 的硬闸门**。同类自建站（Elyxira / TBank / MDExamPrep）普遍是「一个 index.html + 一个 JSON」。更关键的是**防进度丢失**这件事：A02 别名网修复说明你真的踩过并解决了"改一次库用户进度全丢"这个业界级难题。

### A5. 学习闭环完整且自洽
刷题 → 错题 → 间隔回顾（双门槛状态机 + 主观三键）→ 组卷（含"哪条限制最紧"的零命中提示）→ AI 变式 → 英语跨库复习。这条链在商业 App 里是拆开卖的。

### A6. 技术判断上有几个明显正确的取舍
- 英语模块注释承认是"穷人版间隔重复"，但**坚持记 log（封顶 50 条）为将来升级真 SRS 留原料**——这是对的选择，没数据就没法拟合 FSRS。
- 组卷会话键用「卷指纹」而非题目 id 集合——避免了题目增删导致会话失效。
- 清空进度按 `QGROUP` 分类而非 id 前缀——A02 后扩展题主 id 已变，前缀判断会误删。

## 四、劣势（按严重度排序）

### D1. 🔴 记忆算法落后一代 —— 最该修的
固定间隔表 `[1,3,7,15,30]` + 双门槛（连对 ≥4 且跨度 ≥21 天）。问题：
- **无个体差异建模**：FSRS-6 已是 Anki 默认（2025.07 起），在 9,999 个牌组 / 3.5 亿次复习的基准里 **99.6% 用户优于 SM-2**，同等保持率下省 **20–30% 复习量**。
- **阈值拍脑袋**："连对 4 次且 21 天"对已经会的题是过度复习，对真难的题又因为答错即清零（`stage=0, streak=0`）而反复从头来。
- **英语侧同理**：`SCHEDULE` 三档固定表按累计标记次数步进，本质是 SM-2 的静态近似。
- 好在：log 已经记了，升级有原料。

### D2. 🔴 覆盖面只用了 35%
本地爬了 **52 学科 42,105 题**，站点只上 **3 科 14,881 题**。大三/大四科目、执医、考研西综全部躺在 `题源数据/` 里没用。这是最大的"资产闲置"——数据已经在手，差的只是 `ONLY` 白名单 + 一次构建。

### D3. 🟠 合规风险锁死了产品化可能
题库爬自极光，README 自己声明"仅个人学习、非商用、不公开传播"。这意味着它**永远只能是私人工具**，不能开放、不能开源、不能写进作品集。每一分工程投入都无法转化为外部价值——这是所有缺点里最"贵"的一条。

### D4. 🟠 多端同步是假的"同步"
`push` 是 `set()` 全量覆盖 + `reconcile`（按 updatedAt 谁新谁赢），**只有英语做了逐词 merge**。手机和电脑同时刷，后 push 的一端会整个覆盖另一端。真正的多人/多端需要的是 CRDT 或至少字段级 merge。

### D5. 🟠 单人维护 + 隐性知识未沉淀进代码
4,816 行 JS + 5,000 行构建脚本，关键约束（id 网铁律、CSS 特异度陷阱、`spawnSync` 沙箱坑）大量存在于 `.workbuddy/memory/` 而非代码注释/测试。换设备或半年后回来看，重启成本极高。

### D6. 🟡 无社交 / 无 UGC，也就没有纠错回路
医考帮评论区是它真正的护城河（学长学姐口诀、"这题出错了"的集体纠错）。你有纠错功能，但只有你自己看得见——**14,693 条解析里的错误，永远等不到第二个读者**。

### D7. 🟡 无图示 / 视频内容层
蓝基因 3D 解剖、阿虎重难点视频。你的富解析是纯文本 blocks，遇到机制类（信号通路、代谢循环、解剖毗邻）文本效率低于图示。这是"讲解型内容"的结构性缺口。

### D8. 🟡 无参照系
有限时考试但无百分位排名、无估分。做完一套卷不知道"这个正确率在同级什么水平"——商业 App 的排名/估分是低成本高留存的功能。

### D9. 🟡 PWA 而非原生的硬限制
无推送通知。**复习提醒是 SRS 产品的关键留存手段**——自己排的间隔没有人提醒，等于算法算对了一半。iOS 上 PWA 还有后台、存储配额等一堆限制。

### D10. 🟡 AI 变式无质检环节
Jamieson 2025：未 grounded 的 GPT 生成 USMLE 题 **~22% 事实错误、49% 出题规范缺陷**。你的 AI 变式基于本题（有 grounding，好于裸 prompt），但仍无质检/标注/隔离机制。目前"不进组卷池"是对的，但也就意味着它只是个玩具。

| 优先级 | 动作 | 理由 | 成本 |

| **P0** | 剩余 49 科上站 | 数据在手，只改 `ONLY` + 跑 release | **低** |

## 六、一句话总结

**优势是"题源对口 + 解析覆盖 + 完全自控"，劣势是"算法落后一代 + 35% 资产闲置 + 合规锁死产品化"。**
如果只做一件事：把间隔算法换成 FSRS。如果只再做一件事：把剩下 49 科上站——数据都在硬盘上躺着，这是零边际成本的收益。
