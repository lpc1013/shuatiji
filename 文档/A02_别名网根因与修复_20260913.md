## 3. 根因

### 3.1 A02 机制（设计意图，正确）

一题 = **1 个终身主 id + 一串 aliasIds**。运行期 `ALIAS[老id] = 主id`，`qById` 走 `ALIAS[id] || id`，用户 localStorage 无需改写 → 进度零丢失。

### 3.2 断点：扩展组别名候选只有 2 个来源

`build_packs.mjs`（约 337-339 行）：

```js
const aliasSet = new Set(allIds.filter(x => x !== primaryExt));  // ① sourceDetail 里的来源 id
if (prevId && prevId !== primaryExt) aliasSet.add(prevId);       // ② 上一版主 id（按文本指纹反查）
aliasCands = [...aliasSet];
```

- ① `allIds` = `sourceDetail` 的来源 id（`ykb_`/`school_`/`kaoyan_`/`iyixue:`）—— **不含 `ext-<hash>`**（那是站点生成的，不是来源 id）
- ② `prevId` = 上一版 packs 里该题的主 id

**`ext-<hash>` 进别名的唯一通道就是 ②。**

### 3.3 为什么会断

A02 那次构建的基线（`工程/题库调研/packs`）里，扩展题主 id **已经是 srcid**（说明在 A02 之前已有一次构建把 id 换成 srcid 并丢掉了 ext-）：

```
prevId 反查 → 返回 srcid
primaryExt 择优 = allIds.filter(stable)[0] → 也是 srcid
→ prevId === primaryExt → ② 被跳过
→ 旧 ext-<hash> 从未进入 aliasCands
→ 保留 1713（全是极光 oursite / iyixue 源 id），ext- 别名 = 0
```

### 3.4 附带的**设计缺陷**（会持续复发）

> 扩展组构建时**不继承上一版的 `aliasIds`**，只继承"上一版主 id"。

推论：**只要经历 ≥2 次主 id 变更，中间那代的 id 就永久丢失**。即使本次修好（aliasIds 带上 ext-），若下次重建的 PREV 主 id 又是 srcid，**别名会再次被丢**。

→ 所以修复必须 **两步走**：先恢复，再堵漏。

## 4. 修复方案

### Step 0 · 先备份（不可省）

```powershell
# 当前 packs 是 A02 产物，重建前留档
robocopy "题库调研\packs" "E:\_shuatiji_outside\bak_packs_pre_a02fix" /E
```

### Step 1 · 堵漏：改 `build_packs.mjs` 扩展组别名逻辑（**必须早于重建**）

`build_packs.mjs` 约 337-339 行改为：

```js
const aliasSet = new Set(allIds.filter(x => x !== primaryExt));
if (prevId && prevId !== primaryExt) aliasSet.add(prevId);
/* 新增：继承「上一版该题（prevId）挂着的全部别名」——
 * 防「前前版 id」在多次主 id 变更后静默丢失（本次事故的正因）。 */
const prevItem = prevId ? prevPacks.get(prevId) : null;
if (prevItem && prevItem.flags && prevItem.flags.aliasIds)
  for (const a of prevItem.flags.aliasIds) if (a !== primaryExt) aliasSet.add(a);
aliasCands = [...aliasSet];
```

> `prevPacks` 同时保存 `flags`（build_packs.mjs:193 已 `{...q, _subject,_sem,_grp}`），可直接取。

（极光组同位置建议一并加，属加固；极光主 id 恒定 UUID，非必需。）

### Step 2 · 恢复：用含 `ext-` 主 id 的历史基线重建

### Step 3 · 重新生成站点数据 + 发布

## 5. 代价与风险

### 体积（实测）

| 分片 | 题数 | 当前 gz | 注入 ext- 别名后 Δraw | Δgz |
|---|---|---|---|---|
| bio-ext | 3,162 | 225KB | +130KB | ~+43KB |
| immunology-ext | 3,383 | 225KB | +139KB | ~+46KB |
| physiology-ext | 3,435 | 250KB | +141KB | ~+47KB |
| **合计** | **9,980** | 700KB | **+400KB raw** | **~+130KB gz** |

**关键**：分片**懒加载**（打开某科才拉该科分片）→ **首屏/首页/列表体积零影响**；单科做题首屏 +43~47KB gz。符合"轻量 + 分片"既定理念。

| 项 | 等级 | 说明 |
|---|---|---|
| `bak_packs` 主 id 108,018 vs 当前 108,023（差 5） | ⚠️ 中 | 重建前应 diff 这 5 条，确认不引入 id 回退 |
| 跨版本基线 | ⚠️ 中 | bak_packs 是 A02 前快照；新题走 `allIds` 路径（安全），但需跑全量 verify 兜底 |

| 只覆盖 `ext-<sha1>` 形态 | ⚠️ 中 | 本轮只验证了这一种历史 id；nanoid/oursite 变体未查（见 §6） |

## 7. 一句话总结

**A02 的 id 网机制是对的，坏在"首次迁移的基线已经不含旧 id"，且扩展组别名不继承上一版 aliasIds —— 这两点叠加导致 lpc 的 270 条 `ext-` 永久变死链。题没丢，用 A02 前的历史基线重建一次即可 100% 恢复；但必须先打上"继承别名"的补丁，否则下次重建又会丢。**
