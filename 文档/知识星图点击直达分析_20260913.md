# 知识星图「点击直达章节」分析报告

> 现象：成就页「🪐 知识星图 · 章节掌握度」点击星点，没有到达章节。
> 结论先行：**这不是跳转目标选得不好，而是点击根本没生效**——一个真 bug；修好之后，现在的落点（题号导航弹窗）也确实不是最优，建议改为「按掌握状态智能直达章节练习」。
> 依据：`site/app.js`，行号实测。仅分析，未动代码。
> 日期：2026-09-13

---

## 一、根因：星点数据里根本没有章节 id（真 bug）

**证据链：**

1. 星图节点构造（app.js:961-972）：

```js
const nodes = ch.map((c, i) => {
  ...
  return { x, y, rad, tier, pct, practiced, name, ct: ..., i };   // ← 没有 cid 字段
});
```

2. 渲染星点时却引用 `nd.cid`（app.js:976）：

```js
data-act="km-go" data-ch="${esc(nd.cid)}"
```

`nd.cid === undefined` → 所有星点输出 `data-ch="undefined"`。

3. 点击处理（app.js:1802-1806）：

```js
if (act === 'km-go') {
  const c = curSub().chapters.find(x => x.id === t.dataset.ch);   // 永远找不到
  if (c) openChapterNav(c);   // c 为 undefined → 静默返回，连 toast 都没有
  return;
}
```

**结论：点击 100% 无效，且无任何报错/提示**——`esc(undefined)` 输出空串？否：`esc` 通常兜成 `'undefined'` 或空，find 都匹配不上，效果一致。这与「提示语写着“点击星点可直达对应章节练习”（app.js:947）」形成反差，属于承诺了但没兑现的交互。

**修复（1 行）**：app.js:972 的 return 对象补 `cid: c.id` 即可。顺带建议：`km-go` 分支加 else toast（「章节未找到，请刷新重试」），杜绝静默失败。

---

## 二、修好之后：现在的落点是什么？

`km-go` 修复后走 `openChapterNav(c)`（app.js:1128-1147），与题库列表点章节共用，打开的是**「题号导航」弹窗**：

- 全章题号网格（绿=已答对 / 红=答错过 / 白=未刷）；
- 用户再点某个题号 → `jumpToQuestion(c, qi)`（app.js:1149）才真正进入练习并定位到该题。

也就是说，从星图到做题需要 **两跳**：星点 → 弹窗 → 题号 → 练习。

---

## 三、点击后直达哪里比较好？三个方案对比

| 方案 | 行为 | 优点 | 缺点 |
|---|---|---|---|
| A. 保持题号导航弹窗 | 星点 → 弹窗 → 选题号 | 落点自由，能看到全章对错分布；与章节列表行为一致 | 两跳；星图用户意图是「去补」，不是「选座位」 |
| B. 一律直达第 1 题 | 星点 → `jumpToQuestion(c, 0)` | 一跳到位 | 忽略了星图的核心信息：tier（薄弱/一般/扎实/未练）和作答记录，等于白算了掌握度 |
| **C. 按 tier 智能直达（推荐）** | 星点 → `jumpToQuestion(c, 目标题号)`，题号按掌握状态算出 | 一跳到位且落点有依据：薄弱星点直接落在最该补的那道题上 | 需要定义落点规则（下面给了）；`jumpToQuestion` 现成可复用，改动小 |

**推荐 C**。理由：星图的表达语义是「这章你掌握如何」，用户点它的动机几乎总是「这章弱，去练」。落点规则（复用现有数据，全部已有字段）：

| 星点 tier | 落点 |
|---|---|
| **lo 薄弱**（正确率 <40%） | 该章**第一道答错过且未做对**的题（`st.wrong` 命中优先）；没有则在错的题 → 第一道未刷 |
| **mi 一般**（40-70%） | 第一道未刷的题；全刷完 → 第一道答错过的题 |
| **hi 扎实**（≥70%） | 第一道答错过的题（查漏）；没有错题 → 第 1 题 |
| **un 未练** | 第 1 题 |

配套细节：

1. **弹窗不丢**：直达后弹窗里自然关闭（`jumpToQuestion` 自带 `closeModal()`，app.js:1168）。想要全章分布的用户仍可从「题库」页点章节进题号导航，两个入口各司其职；
2. **`<title>` 提示语同步改**（app.js:976）：如 `点击直达本章薄弱题` / `本章未刷 · 点击开始`，让用户点击前就知道会落到哪；
3. **空章节兜底**：`c.questions` 为空时 toast「该章节暂无题目」，不进播放器；
4. **进度保留**：`jumpToQuestion` 已内置断点恢复（读取 saved answers，app.js:1149-1157），直达不会覆盖已有进度，直接复用即可。

## 五、风险与边界

- `jumpToQuestion` 的 qi 与池内下标严格对齐依赖「当前章节题目顺序」（app.js:1152 注释），落点计算必须用 `c.questions` 同一顺序遍历，不能拿 `st.wrong` 的存入顺序；
- 成就页是「当前学科」视图（`curSub()`），星点所在章节必属当前学科，无跨学科跳转问题；
- `data-ch` 修复后注意 `esc()` 输出：`cid` 含特殊字符时 `find` 用的是 dataset 原值，`esc` 只影响 HTML 转义，现有 `data-id` 同款用法已在题库列表验证过，无新增风险。
