# 刷题记 · 页面布局、审美与排版优化报告

审查日期：2026-10-15。线上截图采集时间：北京时间约 15:11–15:24。  
审查站点：[www.lql170.cn](https://www.lql170.cn/)。  
交付：本报告、9 张真实浏览器截图、布局建议示意稿、测量与命中测试证据。未修改或发布业务代码。

## 结论

**建议保留蓝白学习工具的基础风格，优先修复遮挡和阅读问题，再重排信息层级。** 当前已有主题变量、圆角、SVG 图标、焦点样式和减少动态效果支持，无需先做一轮大规模换皮。

从真实页面看，主要问题是：手机首页将大量统计放在学习入口之前；桌面把原本紧凑的卡片横向拉宽，留白没有承担明确作用；小字、浅色标签和繁复装饰同时出现；设置与学习统计没有充分分工。做题页的单列结构较清楚，应保留其专注性。

本报告区分三类依据：**实机确认**为线上浏览器截图或 DOM 命中测试；**代码确认**为本地 CSS／模板规则；**设计建议**为可供选择的优化方向，不冒充可用性实验结论。

> 手机截图来自桌面 Chromium 的窄视口响应式测试，**不是实体 iPhone／Android 拍摄**。请求的 CSS 视口为 390×844 与 1440×1000，另有一张默认 1280×720 做题截图。截图接口返回的部分图像尺寸与 CSS 视口不同，原始像素尺寸见 `screenshots.json`；本次未自行裁切、修图或用示意稿替代实机截图。尚未覆盖实体手机键盘、安全区、系统字体缩放与 Safari 行为。

## 1. 先修复入口与阅读问题

### V01 · 桌面账号按钮被导航遮挡

1440×1000 视口下，首页顶部呈现一条几乎空白的横带，左上角看不到账号按钮。DOM 命中测试确认：账号按钮区域约为 `x=130, y=13.67, width=77.96, height=28.67`；其中心点命中的是 `NAV.tabbar`，并非按钮。

根因对应 `styles.css:394` 附近：顶栏跨两列，侧栏 fixed 从页面顶部开始，侧栏层级 30 高于顶栏的 20。顶栏中的账号位置落在侧栏覆盖范围。

**建议：** 将桌面顶栏明确放到主内容列；或将品牌与账号迁入侧栏的独立区域。避免仅不断提高 z-index，以免顶栏反过来遮挡导航。页面顶部应始终有清晰的品牌、当前学科与账号入口。

**验收：** 900／1024／1280／1440px 均能看到账号入口，中心点命中按钮，键盘能到达。设置页已有另一个登录入口，因此不能把本问题表述为“全站完全无法登录”。

### V02 · 次要文字和状态文字需要更深

根据本地样式的实色前景／背景，按相对亮度公式计算：

| 场景 | 当前色值 | 对比度 |
|---|---|---:|
| 默认次要文字／白卡 | `#76828f`／`#ffffff` | 3.918:1 |
| 默认次要文字／页面底色 | `#76828f`／`#f5f7fb` | 3.653:1 |
| 默认成功文字／成功底色 | `#16a34a`／`#e7f6ee` | 2.953:1 |
| 默认警告标签／警告底色 | `#f59e0b`／`#fef3e0` | 1.954:1 |
| 水墨次要文字／白卡 | `#79898a`／`#ffffff` | 3.647:1 |
| 中国风次要文字／卡片 | `#8c8271`／`#fffcf5` | 3.695:1 |

普通文本采用至少 4.5:1，大号文本在规定条件下可采用 3:1，来自 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。这些数字是**指定色对**的计算，不是全站每个元素均被实机判定不合规；透明底色、纹理及 opacity 需按实际合成结果另验。

**建议：** 拆分“状态标记色”和“状态文字色”。绿色圆点可以鲜明，绿色文字改为更深的绿色；警告文字用深棕色，浅橙用于背景。默认次要文字可先试 `#526173`，对白色约为 6.333:1。不要用给所有小字加粗来弥补对比度不足。

### V03 · 建立可持续的字号层级

`styles.css:33` 默认中字号为 15px；`.small` 为 0.85em，名义值 12.75px；`.tag` 为 0.78em，约 11.7px；`.eng-sec-t` 和模式说明为 0.68em，约 10.2px；阅读页小节标题 0.72em，约 10.8px。部分说明还叠加 opacity，使其更难读。

**建议字号表（产品建议，不是 WCAG 的固定最小字号要求）：**

| 角色 | 推荐范围 | 排版要求 |
|---|---|---|
| 页面标题 | 手机 22–24px，桌面 26–30px | 一页一个主要标题 |
| 区块标题 | 18–20px | 权重 600–700，不必全部 800 |
| 正文／选项 | 16–18px | 中文行高 1.7–1.85 |
| 解析正文 | 16–18px | 行高 1.8–1.95，段间距 12–16px |
| 控件文字 | 14–16px | 重要按钮不依赖微小附注理解 |
| 辅助说明 | 13–14px | 对比度足够，减少不必要 opacity |
| 非关键短标签 | 尽量不低于 12px | 不承担核心信息 |

日期、题号和百分比继续使用等宽数字。字号档位应影响正文与关键控件，不能只放大少数文本。测试 200% 文字放大后的截断与换行。

### V04 · 学科选择器需要明确位置和空间

手机首页中，完整学科名已出现在蓝色主卡标题，下方下拉框却显示成“生物化学（5…”；重复显示没有增加信息，反而让控件看起来损坏。对应 `.hero-subj` 的 `max-width:42%`、较小字号与长选项文案。

**建议：** 用独立上下文栏显示“生物化学 ▾”与“极光／扩展”；题量放到统计或题库概览中。学科名只完整显示一次，等级退到辅助位置。手机必要时将选择器单独占一行，输入／选择控件文字保持约 16px，不依靠缩小字体硬塞。

**验收：** 320／375／390／430px 下三科学科名均可辨，200% 放大仍能操作，控件焦点不被固定栏遮挡。

### V05 · 英语阅读页的响应式覆盖顺序需先纠正

`styles.css:833` 对手机设置 `.engr-word:1.85em`、正文内边距 `16px 16px 22px`，但 `:955` 后又无媒体限制地将它们改成 2.35em 和 `30px 22px 40px`，相同选择器下后者覆盖前者。卡片空白区域也在后面被赋予较大最小高度。

**建议：** 将基础／桌面／手机规则收拢，使用明确断点或 clamp；手机无需继承所有桌面放大间距。重点检查长医学单词、展开后例句和底部评分按钮是否能同时合理呈现。**本次未取得沉浸阅读页截图，不将其实际拥挤程度写成已实机验证。**

## 2. 首页：让下一步学习先出现

### V06 · 从“统计看板”调整为“学习起点”

手机首屏依次出现账号栏、等级大卡、三块统计、两块目标卡，然后才是顺序刷题。未设考试日期仍占据完整卡片，信息量只有一句设置提示。第一次访问时，大面积 0 与未设置状态容易压过真正可执行的学习操作。

**建议顺序：**

1. 上下文：学科＋题库来源。
2. 一个主行动：有断点显示“继续学习”；首次访问显示“选择章节开始”。
3. 今日进度与到期复习，两项轻量摘要。
4. 章节练习、组卷考试、医学单词等次级入口。
5. 掌握度摘要、详细统计链接、低频功能。

等级、XP、打卡和休闲仍可保留，但减少其首屏面积。未设考试日期时用一行“设置考试日期”替代半张空卡。掌握度展开细节放到统计区域；首页只显示一句有行动意义的概览。

**验收方向：** 手机首屏无需滚动即可进入首次练习／继续学习。不要承诺未经实验验证的“提升转化率百分比”。

### V07 · 桌面采用明确主辅栏，减少无意义的横向拉伸

桌面首页的倒计时与今日目标各占约半个主内容宽度，内容本身却很少；六个入口排成四列＋两列，右下留下不对称空位。顶部总题数、今日已练与打卡又被处理成等权大卡。

**建议：** 主栏承载继续学习和核心入口，辅栏承载今日目标／到期复习；常规内容最大宽度控制在约 1040–1160px。保留六个入口时使用三列两行；若按任务重组为三个主要入口，则一行三列。中等屏幕先降两列，不要在 899／900px 之间从窄手机栏突然跳到宽桌面。

阴影只用于强调主行动或浮层；普通统计行以文字层级和间距分组。留白应帮助分组，不应用大卡强行填满空位。

## 3. 做题、题库与英语页

### V08 · 做题页保留专注单列，减少题目前的辅助信息

桌面实际截图中，600px 阅读栏位于中央，两侧留白明显；题号、题型、来源、难度、热度、正确率、收藏数、掌握状态先于题干出现。选项间距较明确、底部确认操作也易于识别，这两点应保留。

**建议：** 默认只展示题号／章节、题型、题干和选项；来源、热度等收进“题目信息”。桌面可试 680–760px 阅读栏，仍限制正文行长，不将题干铺满 1180px。若加入侧边答题卡，必须使用新的专注布局承载，避免重新露出原首页侧栏。

收藏、疑点、纠错降为次级工具行；未选择选项时，确认按钮应给出明确的禁用或引导状态。“看答案”和“确认”保持不同视觉权重。长解析按“答案依据→逐项辨析→易错点→教材出处”组织，减少每段都套彩色卡片。

### V09 · 题库页需要解释层级与空状态

真实题库页同时包含题库／词库切换、搜索、章节选择、错题／收藏／疑点、掌握状态筛选。新用户面对的最终结果却只有“这里还空空如也”，没有解释当前列表是什么，也没有下一步。

**建议：** 将全库检索与“我的错题／收藏／疑点”明确区分。结果上方显示简洁摘要，如“生化 · 极光 · 错题 · 全部状态”；高级条件收进筛选面板。空错题可显示“还没有错题，完成练习后会自动收集”＋“开始练习”。搜索零结果则提供清除筛选，不能共用同一句泛化空态。

章节下拉中的近似重名条目应标明来源或分组，避免用户以为同一章重复出现。这里的建议是增强可辨识性，不在本轮擅自合并题库数据。

### V10 · 英语页让词条更早出现、列宽更稳定

手机截图中，搜索、词库概览、状态摘要、三模式选择、分类和高级筛选占据较大垂直区域；第一条单词约在页面中段才出现。桌面词形、音标、中文与分类沿内容自然排布，词义长短导致标签位置不齐。

**建议：** 模式选择常驻但减少附属说明；学习统计折叠成一行，筛选展示当前条件与结果数。桌面词表可使用“词形／音标／释义／状态”的稳定网格，手机采用两行：第一行词形＋发音，第二行释义。不要为每一行重复显示当前已选分类；仅混合全库结果时保留分类标签。

“查词”和“学习”可共用词库，但突出不同主行动。零进度场景不要堆叠多个 0，让“开始背诵”或“到期复习”成为明确入口。截图中的全库总数与当前分类数量应分别标注口径，避免看成同一指标。

## 4. 设置、主题与组件一致性

### V11 · 设置应先提供设置，统计与说明适当分流

实机设置页先显示云同步、学习数据、完整掌握度，然后才进入偏好设置。用户为了调整字号需要经过重复统计。代码中的备份卡、关于说明仍存在“无账号体系／仅本机”等文案，而页面已有登录与云同步入口。

**建议分组：** 阅读与显示、学习行为、账号与同步、备份与恢复、数据管理、关于。统计保留跳转入口，不在设置里重复整块掌握度。危险操作置于独立底部分组，并使用明确对象和范围文案。

同步状态按“未登录，仅存本机／已连接，最近同步时间／离线，有待同步内容”呈现，避免泛称所有状态都“仅本机”。开关改为原生可聚焦控件或具有完整 switch 语义的按钮；视觉滑块可以小，触控与键盘操作区域应足够。

### V12 · 主题换气质，阅读布局保持稳定

现有主题提供了有辨识度的选择，可以保留。但默认主题已经包含渐变、斜向纹理、卡片顶边线、投影与多色图标；同时使用容易让装饰层多于必要的信息层。

`themes.css` 的横线主题还改变卡片左内边距为 34px，并给部分正文强制 30px 行高，因此其作用不止“换底色”，会改变布局与阅读密度。

**建议：** 默认学习主题使用低纹理底色、轻边框、少量主色；纹理主要放在页面边缘或空白处。主题尽量仅调整色彩与背景，字体、内边距、行高保持稳定。不要把主题名称中的“护眼”当作经过验证的医疗效果表述。

### V13 · 收敛组件规则，减少依赖追加覆盖的美化

样式文件后部持续追加针对 `.hero`、`.engr-*`、`.chip` 等的覆盖，已产生 V05 的明确问题。

**建议：** 建立一组可检查的设计变量：正文、辅助文字、状态文字、边框；间距 4／8／12／16／24／32px；圆角保留约 8／12／16px 三档；阴影分普通面板与浮层两级。每个组件的基础、状态和响应式规则放在一起。

同时统一主按钮、次按钮、轻量文字操作、筛选芯片与纯展示标签。可点击卡片使用真实按钮／链接，保证键盘可达；不用只依赖 cursor:pointer 暗示交互。

触控目标建议为常用动作提供约 44px 的有效区域，但不要误称 WCAG 2.2 AA 的最低值必然为 44px；其目标尺寸条款以 24 CSS px 或满足相应间距／例外条件为基础，参见 [W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

## 5. 推荐实施顺序与验收

| 批次 | 内容 | 完成条件 |
|---|---|---|
| 第一批 | V01–V04，兼修 V05 的样式覆盖 | 桌面入口可见且可点；关键小字可读；手机学科名完整；响应式规则无意外回盖 |
| 第二批 | 首页主行动、桌面主辅布局、题库空态 | 手机首屏有明确学习入口；桌面无四＋二磁贴残行；空态可引导下一步 |
| 第三批 | 英语控制区、设置分组、主题减法 | 第一条学习内容更早出现；常用设置容易找到；切换主题不改变正文基本几何 |
| 持续维护 | 组件变量与回归截图 | 同一批次保存前后截图，覆盖真实数据与空态 |

验收矩阵建议覆盖 320、375／390、768、1024、1440px；另用实体 iOS Safari 和 Android Chromium 检查软键盘、地址栏收缩、安全区、长单词和底部操作栏。放大时的重排参照 [W3C Reflow 说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)，不要简单禁止用户缩放。

需要保留的已有能力：全局 focus-visible、减少动态效果规则、较清晰的选项卡片、移动表格转卡片、可选云同步和简洁模式。不要将这些已存在的功能列为“尚未实现”。
