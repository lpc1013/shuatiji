把 iyixue.top 调研报告里的 A 档（纯前端立刻可做）、B 档（数据已有但未接入）、C 档（渲染层先建好等数据）落地到自建刷题站。

一句话结论：原本躺在 merged2 里从没透传前端的 explanationBlocks（8 万条结构化解析）已经换成前端能直接渲染的富解析分片；站点主体分片反而瘦了约 20%，净体积略降。用户进度零影响（题目 id / 章节 id 一个都没动）。

1. 富解析分片（最大的一块）

原先解析分片是 {题目id: 一坨文本}，前端只做了「### 变标题、换行变 <br>」的粗糙转换——文本里明明写着 Markdown 表格，渲染出来却是一堆竖线。

现在改成 富解析：

结构{bf: 一句话解析, b: [块…]}；块为紧凑数组 [type, sec, title, …payload] typep 段落 · c 提示框 · l 列表 · tb 表格（[列名], [行]） secan 考点解析 · ab 答案依据 · pf 易错点 · cn 临床与操作要点 · tx 教材出处 来源源站 explanationBlocks（已带类型）为主 + 文本 ### 小节 补全其未覆盖的小节，按 sec 去重后合并

为什么必须「blocks + 文本」两条腿

小节源站 blocks文本 ###处置
考点解析 / 答案依据 / 易错点✅ 有（带 type）✅ 有用 blocks，保留类型信息
教材出处❌ 无✅ 4,725 条文本补全 只用 blocks 会丢这 4,725 条
临床与操作要点✅ 少量✅ 少量用 blocks

2. 前端结构化渲染

app.js 新增一组纯函数：explainInner / expBlockHtml / reservedBlocksHtml / qChipsHtml / richToText。

  • 小节卡片：每小节一张卡，段头 3px 竖线，颜色按小节分（解析=蓝 / 答案依据=绿 / 易错点=橙 / 教材出处=灰）
  • 表格真渲染：<table> + 表头 + 斑马纹；760px 以下自动转卡片（td::before 读 data-label，列名不丢）
  • 一句话解析置顶：淡蓝卡 + 「一句话解析」标签
  • 旧格式兼容：分片若还是字符串（或 {t}），照旧渲染，不会白屏
  • 纯文本仍可用：ensureExplain 注入富解析的同时派生 q.explanation，AI 再解析 / 复制 / 旧判断逻辑一处都没坏

5. 新功能：最弱知识点 Top3

借鉴 iyixue.top 的「最弱知识点」，但用的是我们已有的数据：把题目级作答统计（qstat）按知识点标签聚合，取正确率最低的 3 个，点一行直接对该知识点组卷补漏。设了「至少作答 3 次才入榜」的门槛，避免「1 题答错就判定你最弱」的噪声；该学科没有带标签的题时整张卡不出现。

另外把组卷预览从「命中 N 题」升级为「命中 N 题 · 本轮取 M 题 · 预计 X 分钟」；命中为 0 时会指出哪一条限制最紧（逐条临时放开、看题量回升最多的是哪个），比笼统说「没有题」有用。

6. Service Worker：根治 ?v= 那个老坑

新增 site/sw.js，策略是网络优先 + 离线回落：在线永远取最新，断网回落缓存（顺带白得离线可用）。缓存名带版本号，activate 时清掉所有旧的 shuati-*，不会两个版本打架；跨域请求（如 CloudBase 的 AI 出题接口）一律直连不进缓存。

为什么不缓存优先：本站进度全在 localStorage，最怕「index.html 是旧的、分片是新的」这种新旧混排——那正是字段对不上、界面错乱的根源。

10. 遗留

  • 视觉需你本地确认：本机无可用的浏览器自动化（headless Chrome 系统级崩溃），布局/配色只能靠你打开看。
  • 站点仍只有 3 科：医学英语数据已就绪（3,783 词 + PubMed 例句），尚未接站。
  • 标签覆盖率偏低：tags 仅约 1 万题有值（跨源题以极光为主记录时不带扩展侧的标签）。若要补，得改 merge2.mjs 让合并组的标签取并集，再重跑三件套。
  • questionRevision 不进前端：有意为之（前端暂不消费，占 0.3MB）；将来要做「题干变更 → 复习记录定向失效」时加回即可。
