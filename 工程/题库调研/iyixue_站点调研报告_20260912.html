03排印与布局：可直接照搬的 9 条

  1. 正文 15px / 行高 1.65；解析长文额外放宽到 1.85。行高按「阅读密度」分档，而不是全站一个值。
  2. 解析正文限宽 max-width:78ch——中文长文最舒适的行长，避免大屏上一行 40 个字。
  3. 大标题收紧字距：h1{font-size:clamp(29px,3vw,46px); letter-spacing:-.04em; line-height:1.08}。字号随视口流体缩放，字距反向补偿。
  4. 所有数字用 font-variant-numeric:tabular-nums：题数、页码、正确率、倒计时全部等宽对齐，数字变化时不跳动。这是刷题类界面的基本功。
  5. 英文小标签做视觉层次：letter-spacing:.18em + 9–11px + 主色，用作眉标（STUDY RX、TEXTBOOK EVIDENCE、MEMO、POINTS）。中文标题 + 英文眉标是其核心排版语言。
  6. 分段标题带 3px 左竖线：.explanation-section-header::before{width:3px;height:12px;background:var(--accent)}——零成本建立层级。
  7. 断点主轴 760px（全套 CSS 里出现 23 次，是绝对主断点），次轴 1199 / 900 / 620px。单轴优先，不搞十套断点。
  8. 表格在移动端自动降级为卡片：@media(max-width:760px) 下隐藏 thead，每个 td 用 ::before{content:attr(data-label)} 显示列名——渲染时就把列名写进 data-label。宽表在手机上不再横向滚动。
  9. 横向溢出用 overflow-x:clip，并用 @supports not (overflow-x:clip) 回退 hidden——因为 hidden 会创建滚动容器、破坏 sticky 头部，clip 不会。这是很细的一手。
触控与可访问性（都在细节里）：按钮统一 min-height:44px（iOS 触控推荐下限）；:focus-visible{outline:3px solid …; outline-offset:3px} 键盘可达；.skip-link 跳到主内容；aria-live/aria-expanded/aria-pressed/role="note" 齐备；@media(prefers-reduced-motion:reduce) 关掉全部动效。

04九个「闲置空字段」的真实归宿（核心）

最重要的结论先讲：这些字段在我们的 iyixue_top/ 分片里是空的，但在 iyixue.top 的前端，每一个都有已上线运行的渲染组件、样式类与偏好开关。也就是说——它们不是废弃字段，而是「渲染层已完成、数据层待生成」的接口预留位。参考价值在于：它提前把「这些字段未来会长什么样、会被怎么用」演示了一遍。

推论：我们的站点即使现在拿不到数据，也可以先把渲染通道建好；等 AI 生成管线接通，字段一到即显示，无需再改前端。
mnemonicstring记忆口诀卡 MEMO

答题后展示的大字口诀卡，与解析分开陈列，视觉上刻意「重」——17px 加粗、行高 1.8、左侧 146px 的 MEMO 标签栏。

renderMnemonic(q) → <aside class="mnemonic-card"> <header><span>MEMO</span><h3>记忆口诀</h3></header> <p>{mnemonic}</p></aside>

受偏好开关控制：「显示记忆口诀 — 显示口诀与助记卡片」。字号在移动端从 17px 降到 15px。

studyPoints[{title, body}]考点折叠卡 POINTS

与口诀卡同款外层容器（.mnemonic-card.studypoint-card），内部改成逐条折叠：每条 title 作 summary、body 作正文，用原生 <details> 实现，带 ▸/▾ 箭头指示。

renderStudyPoints(q) → <aside class="mnemonic-card studypoint-card"> <header><span>POINTS</span><h3>考点</h3></header> {points.map(p => <details class="studypoint-item"> <summary>{p.title}</summary><p>{p.body}</p></details>)}</aside>

设计意图：口诀是「记住」，考点是「展开理解」——同一位置两种信息密度，默认折叠以免解析过长。

reasoningSteps[{evidence, inference}]推理路径（有序列表）

这是全套设计里教学价值最高的一个组件：把「怎么想到答案」拆成链式步骤，每步两行——上行灰字是题干/教材给出的证据，下行黑字加粗是由证据得出的推断。

renderReasoningSteps(q) → <section class="reasoning-path"> <h4>推理路径</h4><ol> {steps.map(s => <li><span>{s.evidence||'题干信息'}</span> <strong>{s.inference}</strong></li>)}</ol></section>

过滤条件：evidence 或 inference 至少有一个非空才渲染；全空则整块不出现。

optionExplanations[{option, explanation, typicalScenario?}]选项辨析（逐项）

把解析从「整段落」拆到「每一个选项」：左侧 30px 圆形字母徽标，右侧说明为何对/错；若有 typicalScenario 则追加一行「典型场景」灰色小字——即把错误选项对应到什么临床情境上，防再错。

renderOptionExplanations(q) → <section class="option-explanations"> <h4>选项辨析</h4> {items.map(i => <article><b>{i.option}</b> <div><p>{i.explanation}</p> {i.typicalScenario && <small>典型场景：{i.typicalScenario}</small>}</div> </article>)}</section>

与推理路径同属一组，由偏好「显示详细解析 — 显示推理路径与逐项解析」统一开关。

memoryCards[{title, content, memoryCue, contrast}]知识点背诵（错题本第二模式）

这是唯一跨页面复用的字段——不在做题页出现，而是驱动「错题本」的第二视图：错题本有「题目模式 / 知识点背诵」两个 tab（状态存 medq:wrongbook-mode:v1）。

背诵模式把同一张知识卡在所有错题里出现的位置聚合成一个分组卡，按「命中题数」倒序排——一道题错得多，它的知识点卡就浮到最上面。

分组键 = title + "\0" + content 组内字段 = { title, content, memoryCue, contrast, records[] } 排序 = 按 records.length 降序 → 再按 title 中文排序 渲染 = <section class="panel wrongbook-knowledge-card"> eyebrow「知识点背诵」+ <h3>{title}</h3> + 「{n} 题」 <p class="studypoint-body">{content}</p> {memoryCue && <div class="wrongbook-mnemonic">…} ← 记忆提示

注意 contrast 字段：命名为「对比」，是给「容易混淆的一对概念」预留的（如「心绞痛 vs 心梗」）。目前前端已取用，是成对记忆的设计位。

knowledgePoint / knowledgePointsstring / string[]知识点标签 + 最弱知识点 Top3

这个字段的用法比想象中深，它同时支撑四件事：

  1. 标签 chip 展示：题干上方正式知识点标签，偏好「显示题目标签 — 显示正式知识点标签」控制。
  2. 笔记归类：「我的笔记」页声明「按学科与正式知识点自动归类」，即用标签做二级目录。
  3. 知识点级掌握度：把作答记录按标签聚合成「知识点掌握度」，并产出最弱知识点 Top3（正确率升序）。
  4. 元数据标签过滤：内置 isMetadataTag() 剔除「学科名 / A型题 / A 必背 / 高频 / 反馈 / 待整理」等非知识点标签——否则这些词会污染知识点统计。这一条我们做统计时必须照抄。

knowledgePoint（单数）则是贡献题编辑器里的单值输入位，与复数并存。

suggestedTagsstring[]标签建议（贡献题编辑器）

用于「用户投稿题目」场景：AI/用户给出的标签建议，与正式 tags 去重合并后展示在一个输入框里供老师采纳。

value = [...(tags || []), ...(suggestedTags || [])].filter(去重).join('、') placeholder = "例如：病史采集、诱导性提问"

对我们而言这个字段价值不高（我们不做 UGC 投稿），但它揭示了一个模式：tags 是权威标签，suggestedTags 是待审建议——若未来接入 AI 自动打标，正好沿用这个「建议 / 正式」二分。

frequencyLevelhigh / medium / low考频筛选 + 复习队列权重

两处使用，一前一后：

  1. 抽题前：高级筛选里的「考频」三选（高/中/低频），与章节、年份、难度、题型、作答状态并列，参与 previewSession 预计题量计算。
  2. 复习排序：dueReviews() 的排序末位权重——先按「上次是否做错 → 到期时间 → 错题次数」，最后才轮到「高频题优先」。即考频是排序的最后一道 tiebreaker，不喧宾夺主。

另一套等价表示法：代码里同时兼容 A 必背 / B 高频 / C 常规（考研中心「高频考点榜」用）。isMetadataTag() 把这两套写法都当作元数据过滤掉，说明它既可以当筛选维度，也可能被误写进 tags——两种都要防。

explanationMetaobject教材依据卡 + A/B/C 证据分级

这是整套设计里最重的机制：为「AI 生成的解析是否可信」设计的分级与溯源体系。

证据分级（自动推导，也可显式指定）

级别判定条件（mode）对用户的说辞
Atextbook「教材直接支持 — 结论与所示教材证据直接对应」
Btextbook_reasoning「教材原则 + 病例推理 — 教材卡片只证明相关原理；病例结论来自题干线索推理，并非教材原文」
Cgeneral_knowledge「通识生成 — 未找到达到阈值的教材证据，本解析不是教材来源，必须人工复核」（C 级直接隐藏教材依据区）

教材依据卡的结构

explanationMeta = { mode: 'textbook' | 'textbook_reasoning' | 'general_knowledge' | 'manual', model, score, evidenceGrade: 'A' | 'B' | 'C', evidence: [{ textbook, version, // 教材名 + 版本 sourcePage, // 课本实际页码 → 左侧大号数字「页」牌 quote, // 教材原文（可折叠展开） excerpt, // 关键原句（默认显示，40 字内） contextSummary, // AI 整理后的上下文摘要（可折叠） highlights[], // 需要高亮的术语 score // 检索相关度 }] }

三处细节值得学：

  • 原文术语自动高亮：把「选项去前缀的文本 + 题干分词 + 显式 highlights」取并集，在教材原文里把命中的术语标红加粗（.evidence-origin-mark）——用户一眼看到「答案的依据在这句话里」。
  • 双层折叠：「查看整理后的上下文（AI 整理 / 本地整理）」与「查看教材原文（原始记录）」分开，既不掩盖原文，也不强迫阅读。
  • 教材数量自适应：grid-template-columns:repeat(auto-fit,minmax(min(100%,460px),1fr)) —— 一本教材占满、多本自动流式分栏。
  • 每本教材一个稳定色相：stableHue(教材名|版本)（FNV-1a 哈希取模 360），同一本书永远同一个颜色，卡片不花。
顺带解开的谜：questionRevision（qv1-哈希）是干什么的。
它对「题型 + 题干 + 病例 + 选项 + 答案 + 短解析 + 解析块 + 选项解析 + 推理步骤 + 学习要点」做稳定哈希（键排序后序列化，保证同内容同哈希）。每次加载题目时执行 reconcileQuestionRevisions()：只要哈希变了，就自动删除该题的复习记录。
理由很硬：题目的答案或解析被修订后，基于旧版本形成的「已掌握」判断是无效的，必须重做。这比我们目前「保守地永不变更 id、靠别名兜底」更主动。我们未来若修订题干/答案，可直接借用这个机制做定向失效。

05其余高价值机制（可借鉴度排序）

5.1 间隔复习算法（SM-2 变体，纯前端实现）

四档状态 + 五档间隔，判定同时看连续正确次数和持续时间跨度——不是简单地「连对几题就算会」。

条件状态下次复习
答错learning+1 天
连对 1 次learning+3 天
连对 ≥2 次consolidating+7 天
连对 ≥3 次 且 跨度 ≥7 天consolidating+14 天
连对 ≥4 次 且 跨度 ≥21 天mastered+30 天

复习桶分 6 类（决定进哪个列表）：excluded（手动移出）/ mastered / repeated（错过 ≥2 次）/ due（到期）/ new-wrong / learning。

5.2 知识点级掌握度会反向拉长题目复习间隔

这是它最聪明的一处：知识点掌握度不只看单题。

知识点 mastered 需同时满足：作答过 ≥3 题 · 首末作答跨度 ≥7 天 · 正确率 ≥80% · 最近连续 3 题全对 然后 effectiveReviewState()： 若该题的所有标签均已 mastered → 该题的复习间隔取「这些标签间隔的最小值」（依据标记为 knowledge-tag） → 并且在题目记录被手动置为 mastered 时，会把它降级回 consolidating/learning 重新走流程

含义：单题答对不等于掌握，但它所属的知识点整体掌握后，题目本身也可以延长复习周期——省下时间给真正的薄弱点。

5.3 抽题前的「预计题量 + 预计时长 + 冲突提示」

调整任一筛选条件即实时计算并回显，且能解释「为什么没题」。

previewSession() 返回： available 符合条件题数 count 实际抽取数 estimatedMinutes Math.ceil(count × 0.9) ← 每 0.9 分钟一题 recentDuplicates 最近 7 天做过的重复题数 distribution 各学科题数分布 blockedReasons 冲突诊断，例如： 「“已掌握”与“排除已掌握”互相冲突」 「排除最近 7 天已做题后没有剩余题目」 「所选学科或章节与其他条件组合后没有题目」

这个「给失败原因、不给空列表」的做法，能显著降低用户困惑。

5.4 选项排除只存会话内存，绝不入库

eliminatedOptions = new Map() // key = `${sessionId}:${questionId}`，值 Set<字母> // 注释原文：「仅会话内存，不入库、不同步」

排除法只是临场辅助，不应影响历史正确率与掌握度统计。这是个很容易做错的边界。

5.5 答题后的反思层（错因 / 掌握自评 / 复习感受）

  • 复习感受 2 档：「还不熟」→ 强制 1 天后再复习、状态回落 learning；「暂时清楚」→ 不改记录。
  • 掌握开关：一键移出复习列表，再按一次取消。
  • 错因 5 类：knowledge 知识性 / confusion 概念混淆 / missed-clue 漏看线索 / calculation 计算失误 / guess 蒙的。
  • 掌握自评 3 档：again / uncertain / mastered。

全部标注「可直接跳过」——不强迫填写，但提供了归因数据。

5.6 背题模式（memorize）：独立于作答流程

「直接看答案，不计入作答和正确率」，带病例背景框（caseInfo）、短解析（briefExplanation）置顶、口诀与考点，左右方向键翻题，退出后可续接位置。它的实现刻意做成独立模块（memorize.js 仅 3.3KB），与练习流程完全解耦。

5.7 PWA 与离线题库包

  • Service Worker 用「网络优先 + 离线回落」，理由是「避免新旧版本混排」；缓存名带版本号 medq-shell-v63，activate 时自动清掉所有旧的 medq-shell-*。这直接解决了我们「改 app.js 必须手改 index.html 的 ?v=」的痛点。
  • 离线题库包：整包下载后按 checksum 校验 + 复用，会话里标记「离线题库包」，并跳过在线修订对账。
  • 导航请求失败回落到缓存的 /index.html；/api/ 与跨域请求不拦截。

5.8 讨论区与纠错

每题下方有「可选反馈」（表态 chip，可切换选中态）+ 讨论帖（作者头像字母、时间、回复、最多 500 字）；另有独立纠错入口，问题类型 4 种（答案错误 / 解析有误 / 题干选项问题 / 其他）+ 200 字补充，并提示「同一道题只需反馈一次」。

5.9 偏好设置的实现方式

11 个开关，状态用反向键存储以避免默认值歧义：

showMnemonic → 存 hideMnemonic (invert) showSource → 存 hideSource (invert) showDifficulty → 存 hideErrorProne(invert) 其余：showQuestionTags / showDetailedAnalysis / showPitfalls / showReactions / showDiscussion / showMotion / examSimpleMode / clickToSubmit

「点击选项自动提交」「做对自动下一题」「考试简洁模式」等也都在这层，做题节奏交给用户自己定。
