# 刷题记 · 「放松功能」技术评估（小游戏接入方案）

- **评估日期**：2026-09-13
- **背景**：在刷题记（site/，纯前端 PWA，CloudBase 静态托管 `shuatiji-xxx.service.tcloudbase.com`）中加入"放松一下"入口，点击后玩用户已发布的小游戏（当前：3D 游戏 / 帝成观止卡牌，均不在 site 工作区内，属独立产物）。
- **约束（来自审计报告 + 部署形态）**：
  - 产品理念：**轻量 + 个人自用 + 首屏小**（用户 0912 明确）。
  - 托管：CloudBase Hosting，`index.html` 在根 `/`，**支持子路径部署 → 同域 `/games/xxx/` 无跨域**。
  - 现状坑：部署目录 596MB（A05，D 级）；SW 缓存无体积上限（C01）；门禁缺"未登录本地降级"出口（A01 真实问题，待修）。

---

## 1. 三方案对比

| 方案 | 做法 | 首屏影响 | 维护成本 | 体验 | 离线 | 我的判断 |
|---|---|---|---|---|---|---|
| **A. 外链** | "放松 🎮"按钮 `window.open(游戏地址)` 或 `<a target="_blank">` | 零 | 最低（游戏独立部署） | 跳出站点、开新标签，易"回不来" | 取决于游戏本身 | 最低成本备选 |
| **B. iframe 同域内嵌（推荐）** | 游戏部署到 `shuatiji-xxx/games/3d/`，刷题记加一个"放松"全屏 view，`<iframe src="/games/3d/">` **懒加载** | 零（点开才拉） | 中（两份部署，但解耦） | 留在站内、全屏铺满、可"×返回" | 游戏资源需进 SW 缓存才离线 | **✅ 推荐** |
| **C. 直接内嵌源码** | 把游戏 HTML/JS 融进 site/ 的 view | 大（three.js 等资源进首屏/SW） | 高（耦合，互相拖累） | 最"一体" | 跟随站点 | **❌ 反对** |

### 为什么反对 C（直接内嵌）
1. 直接违反"轻量首屏"——3D 游戏用 three.js 等，资源进首屏会让 D 级部署卫生雪上加霜、撑爆 SW 缓存（C01）。
2. 游戏与刷题记强耦合：游戏迭代要重新走 site 的验证/发布流程，反之亦然。
3. 会把 A05 好不容易要拆出来的 `tavern/` 类噪音又塞回核心目录。

### 为什么推荐 B（iframe 同域内嵌）
1. **体验上"像站内功能"，工程上"是独立产物"**：用户感觉在刷题记里玩游戏，但游戏代码、构建、部署完全隔离，互不污染。
2. **同域无跨域**：`/games/3d/` 与 `/` 同 origin，`postMessage` 可双向通信（记录放松时长、游戏内"退出"按钮通知父页返回）。
3. **懒加载保护首屏**：iframe 首次点击才设 `src`，不拖累首屏体积与 SW 预缓存。
4. **契合 A05 修复**：游戏放"发布白名单目录"外的独立子产物区，正好和要挪走的 `tavern/`/`.bak_*` 一起治理。

> A（外链）只在"游戏已在某第三方域名、且你不想动部署"时作为 10 分钟兜底。一旦游戏也是 CloudBase 托管，B 和 A 成本差极小，但体验差很多——这时代价上 B 完胜。

## 2. 推荐方案 B 的落地技术清单

### 2.1 游戏侧（独立产物，不动 site/）
- 把 3D 游戏 / 帝成观止各自打包为**自包含静态产物**（HTML + JS + 资源，相对路径引用，不依赖绝对域）。
- 部署到 CloudBase Hosting 子路径：
  - `shuatiji-xxx.service.tcloudbase.com/games/3d/`
  - `shuatiji-xxx.service.tcloudbase.com/games/dcz/`
- 可选增强：游戏内监听 `window.parent.postMessage`，支持 `parent.postMessage({type:'relax-exit'})` 让"结束"按钮通知刷题记返回主界面。

### 2.2 刷题记侧（site/ 改动）
1. **入口**：首页加"放松一下 🎮"卡片，或在底部 tab 加一个"放松"tab（推荐 tab——和"刷题/错题/统计/单词"并列，扩展性好）。
2. **视图**：新增全屏 view `#relaxView`，内部 `<iframe id="gameFrame" src="about:blank">`。
3. **懒加载（关键）**：点开"放松"才 `gameFrame.src = '/games/3d/'`；关闭时 `gameFrame.src = 'about:blank'` 释放内存。
4. **全屏铺满**：iframe 用 `position:fixed; inset:0; width:100%; height:100%`（避开 `100vh` 移动端跳动），`allow="fullscreen; gamepad; autoplay"`。
5. **返回**：右上角"× 返回"按钮 + 监听 `message` 事件（`e.data.type==='relax-exit'` 时回到主 view）。
6. **多游戏**：用一个简单清单渲染入口（3D / 帝成观止），各对应一个 `/games/xxx/`。
7. **进度记录（可选）**：用 `postMessage` 把"本次放松 N 分钟"回传，写进 `st.relax`（或独立 key），在统计页显示"学习 X 题 · 放松 Y 分钟"——呼应"学习/休息平衡"的卖点。

### 2.3 与既有审计项的联动
| 审计项 | 联动动作 |
|---|---|
| **A05 发布白名单** | 借这次把 `site_dist/` 建成发布目录，游戏放 `site_dist/games/` 子区；`tavern/`/`.bak_*`/`database_export*.json` 一并移出 |
| **C01 SW 体积上限** | 若游戏要离线，需把 `/games/*` 资源纳入 SW 缓存——但**必须加体积上限**（否则 three.js 撑爆 Cache Storage）；否则游戏保持"需联网" |
| **A01 离线/登录** | 修复门禁后，刷题记本体可离线；游戏离线另行处理（见上） |
| **C03 PWA** | 若加"放松"tab，记得在 SW 预缓存清单里带上该 view 的 js/css（懒加载的 iframe 不进首屏预缓存即可） |

### 2.4 移动端注意点
- iframe 在 iOS Safari 的 `100vh` 抖动 → 用 `position:fixed;inset:0` 而非 `height:100vh`。
- 游戏若用 `requestFullscreen` / 虚拟摇杆，iframe 需 `allow="fullscreen; gamepad"`。
- 键盘类（帝成观止可能用键盘）→ 移动端需确认游戏自身有触屏适配，否则手机上玩不了。

## 3. 按你的实际游戏清单落地（已确认：纯个人自用 + 离线优先）

你有 4 个候选：3D 游戏（单文件）、股票模拟器（多文件/已上线）、羊了个羊（多文件/已上线）、帝成观止（多文件/已上线）。

| 游戏 | 形态 | 线上地址 | 推荐接入 | 离线策略 |
|---|---|---|---|---|
| 3D 游戏 | 单文件自包含 HTML | 无 | 部署到 `/games/3d/`，iframe 同域内嵌 | ✅ 进 SW 离线缓存（自包含、体积小，零负担） |
| 股票模拟器 | 多文件需构建 | 已有 | iframe 指向现有 URL（联网玩） | 保持联网；欲离线需 build 进 `/games/` 并加 SW 上限 |
| 羊了个羊 | 多文件需构建 | 已有 | 同上 | 同上 |
| 帝成观止 | 多文件需构建 | 已有 | 同上 | 同上 |

### 分层原则
- **自包含单文件游戏（3D）→ 离线首选**：直接进同域 `/games/3d/` + SW 缓存，纯个人自用离线可玩，不撑爆缓存（C01 治理对它无压力）。
- **已有线上地址的多文件游戏 → iframe 指向现有 URL**：用 `iframe` 而非 `window.open`，体验留在站内；缺点是要联网。若你坚持离线，再把它们 build 成静态产物部署到同域 `/games/xxx/` 并启用 SW 体积上限（见 C01）。
- **入口**：底部新增"放松"tab 比首页卡片更合适（4 个游戏任选，tab 扩展性最好，与"刷题/错题/统计/单词"并列）。

### 修正（用户 2026-09-13 指正）：门禁服务于跨设备同步，个人自用更该保留，而非降级
登录门禁的用途是**跨设备数据通用**——手机刷、电脑续，进度经云端同步。纯个人自用反而最依赖它（多设备学习），所以**门禁不该降级，反而该保留**。

A01 的真实问题不是"不该有门禁"，而是"无 token 即全屏登录墙、缺本地降级出口"：
- 断网 / 首次打开没网时，本地 localStorage 进度完好却被遮罩锁死，无法学习；
- 与 `app.js:845/861`「纯本地个人学习站」文案冲突（行为 cloud-mandatory，承诺 local-first）。

**正确修法：保留门禁 + 补未登录本地降级**。
- 未登录时静默走 localStorage 本地用，正常进入学习，不再弹墙；
- 用户主动点"登录/同步"才出现账号卡，登录后一键把本地进度合并上云，实现跨设备通用；
- `validateAndEnter` 失败（断网/云故障）也隐藏门禁、放行本地。

与放松功能的关系：修 A01（补本地降级入口）+ 建发布白名单（A05）+ 加放松 tab 可**同批做**，但动机不是"降级门禁"，而是"补离线出口 + 治理部署卫生"。

### 下一步动手所需信息

1. **3D 游戏文件路径**（单文件 HTML，用于部署到 `/games/3d/`）。

3. 确认入口形式：底部"放松"tab（推荐）还是首页卡片。

## 4. 一句话结论

**不要直接内嵌源码（C），也不要只丢外链（A 除非游戏本就在第三方域）。用「同域 iframe 懒加载内嵌（B）」：游戏独立部署到 `/games/xxx/`，刷题记内加一个全屏 view 懒加载它。** 这既符合"轻量首屏"，又借机把 A05 部署卫生一起治理，体验还留在站内。
