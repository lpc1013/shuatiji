## 1. 视觉风格审计

> 本机无浏览器，以下「⚠️ 需本地复核」项请用户在 `node 工程/题库调研/serve_site.mjs 8790` 下实测（file:// 会被 CORS 拦）。

| 项 | 现状 | 判断 |

| 四态掌握指示 | `.mdot` 矢量圆点 + `.mseg` 斜纹灰段 | 设计合理；小屏可能拥挤，⚠️ 需本地看 |

## 3. 代码质量与潜在 bug（已逐项核实）

### 3.1 XSS 面 — 已收敛（原预判下调）
- 所有动态 HTML 注入均走 `esc()`：`q.content`/`q.caseInfo`/`q.options`/`q.images`/`q.year` 等（app.js:184-185,265,290-295,451-522,756-757,880-888,1191-1214）。
- 用户纠错文本 `fbrec.text` 也 `esc()`（app.js:1214）。
- `md()` 先 `esc()` 再套 markdown（app.js:405-413），**`<script>` 等被转义为实体，不会执行**。
- **残余风险（P2）**：`md()` 应用于管线派生字段（studyPoints/optionExplanations/memoryCards）。当前数据可信，风险极低；但若未来 AI 变式文本未经净化直接进这些字段，会按 markdown 渲染。建议加一层白名单标签或 DOMPurify。

### 3.2 save() 静默吞错（P1，R6）
`app.js:346` `function save(){ try{ localStorage.setItem(...) }catch(e){} }` —— 配额溢出（`QuotaExceededError`）被静默吞掉。后果：用户的最新作答「看似保存成功（别处 toast 成功），实际磁盘未更新」。14,880 题 ×（qstat + wrong/fav/doubt/mastered + examHistory）+ 英语进度，全量序列化进同一 key，逼近 5MB 阈值不无可能。建议：`catch` 中检测 `QuotaExceededError`，弹「存储空间不足，请清空部分进度」并引导到清空页。

### 3.3 导入校验（P2，R9）
`app.js:1700-1713`：解析后仅查 `loaded.global` 是否存在，无 `version` 字段校验，也不重跑 `migrateChapterKeys`/`migrateExamSessionKeys`。旧格式导出覆盖当前全量状态（含 `global.xp/badges/checkin/settings` 与 `st.note/st.feedback`，这些本应受保护）。建议：导入前比对 `state.__v`/manifest version，旧版给「将丢失新功能」警告，并在 `S=loaded` 后强制重跑迁移。

### 3.4 选项乱序稳定性 — 设计良好（正项）
`optView()`（features.js:302-319）以 `q.id` 为种子做确定性 FNV 哈希置换，并缓存于 `shakeCache`。**同一题每次加载顺序固定**，复习时不乱跳，且避免「每次刷新变序」干扰。这是优于随机乱序的设计，保留。

### 3.5 考试键指纹（P1，R5）
- 考试入口 `requestStart(exam,'exam',{minutes,single:nS,multi:nM,src:'filter',cond:condSummary()})`（features.js:290）。
- 键 `examKeyOf` = `src|cond|single|multi`（app.js:1037-1043）。
- `cond` 来自 `condSummary()`，**应已编码全部筛选维度**；若如此，不同配置→不同键→不串卷。
- **残留风险**：若 `condSummary()` 漏掉 `poolFor` 实际过滤的任一维度（`grp/types/diffs/srcs/yFrom/yTo/hotMin/accFrom/accTo/status/excludeMastered`），则两卷同键 → 互相覆盖/串卷。请核对 `condSummary` 实现是否穷举上述字段。
- 练习路径 `requestStart(p,'practice',{},null)` 键为 null（app.js:1147 仅 exam 带指纹），每次全新，不串卷，符合预期。

## 4. 数据 / 架构 / 安全对抗性风险（重点）

### R1 强制登录门禁 fails-closed（P0，最高危）
`sync.js:426-443` `init()`：
```
if (token) { hideGate(); validateAndEnter(); }   // 有 token：静默 pull
else { showGate(); }                              // 无 token：直接弹门禁
```
`validateAndEnter()`（sync.js:357-364）：`pull` 成功→进入；**失败（网络错误/CloudBase 故障）即 `clearAuth(); showGate()`**。

后果：
1. **首次用户被挡**：无 token → 必须注册/登录才能学习。一个只想刷题的人被卡在登录墙前。
2. **断网/云端故障即踢出**：返回用户本地进度完好（localStorage），但 `body.gated` 遮罩锁死整页，离线无法学习。
3. 学习工具的正确模型是 **local-first**：登录只增强「云端同步」，绝不该阻断本地学习。

**必修**：改为——无 token / 网络失败时**不弹门禁**，正常进入学习；门禁只在「用户主动点登录/需同步」时出现。或至少 `validateAndEnter` 失败路径 `hideGate()` 而非 `showGate()`。

### R2 ext id 内容寻址 → 孤儿进度（P0）
ext 题 id = `ext-<sha1(归一化题干)>`。任一题干编辑（错别字、措辞、选项值）→ hash 变 → 旧 `m1/m2/m3`、qstat、wrong/fav/doubt 全部指向新 id 不存在的旧键，**显示为「进度消失」且继续占 localStorage**。merged2 后续必改题干 → 必然发生，属定时炸弹。极光 id 为原始 UUID 不受影响。

**必修**：引入 ext id 别名映射（旧 hash→新 hash，或归一化题干→主 id），或在 build 阶段做「题干近似匹配回写旧进度」；至少提供一次性迁移脚本。

### R3 同步 last-write-wins（P0）
`reconcile` 按时间戳整块覆盖（sync.js）。多端各标记、或同设备重登后 pull→本地被云端旧时间戳覆盖 → **一面学习标记静默丢失**，无逐字段合并、无冲突提示。对「每道题的掌握状态」这类标记型数据，等于数据丢失。

**必修**：改为逐题/逐字段合并（以每题最近变更时间而非整包时间裁决），或引入 vector clock；至少对 wrong/fav/doubt/mastered/qstat 做 field-level merge。

### R4 / R7 功能残缺与范围（P1）
见第 2 节：图片/病例空态、仅 3 科上线、仅 lql AI。对外交付前必须补齐或显式声明「预览版」。

### R10 SW 与本地打开（P2）
网络优先 + 版本化缓存 `shuati-shell-v2`（sw.js）设计合理；但 `index.html` 的 `?v=20260913b` 手动改写易漏。建议 build 注入版本号。另：若用户直接 `file://` 双击打开，SW/manifest 因 CORS 失效 → 站点崩。**建议**在 `init` 加 `if(location.protocol==='file:')` 友好提示「请通过本地服务器打开」。
