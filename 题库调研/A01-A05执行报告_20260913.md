## 二、A02「统一 id 网」怎么落地

一题 = **1 个终身主 id** + 一串 `flags.aliasIds`。

**主 id 优先级**：上一版 packs 在用 → 源站稳定 id（`ykb_<年月>_<卷号>_<题号>` / `school_…`）→ 上一版 `ext-<hash>`（按文本指纹反查拿回）→ `ext-<hash(dupKey)>` 兜底。

**运行期三层**：
1. 分片加载时建表 `ALIAS[别名] = 主id`、`QGROUP[题id/别名] = 题库`；
2. `qById(id)` 用 `ALIAS[id] || id` 间接寻址（错题本/收藏/复习计划不再「查无此题」）；
3. `normalizeSubjectIds(sid)` 把本机 state 里的旧 id **一次性改写为主 id**（数组换元素并去重、map 换 key、会话换 `qids[].id`/`answers` key），**幂等**。

### 实施中抓出的三个真问题（都已修）

1. **反查字段写错 → 题库翻倍**
   建反查表时读的是 merge2 的短字段 `q.q/q.o`，而 packs item 用的是**长字段** `stem/options` → 指纹恒等、命中 0 → 兜底补回 65,010 条 → 题库涨到 173,028；且兜底段还原时也用短字段 → **补出 65,011 条「空题干」废题**。
   修后：基线 108,809 → **反查命中 64,997 / 65,010**，兜底仅 **5 条**，总数 **108,023**（=108,018 + 5），空题干 1 条（历史遗留）。
2. **主 id 撞车**
   同源题因题干脏/净差异被 merge2 拆成两条，两条却指向同一个源 id → 20 对主 id 重复（站点上两题共用一个进度键）。
   加 `usedPrimary` 唯一性守卫 + **别名延迟落盘**（主 id 全定完，再剔除「恰好是别题主 id」的别名候选，否则 `ALIAS` 会把题指错）→ 主 id 重复 **0**、别名冲突 **0**。
3. **清空进度的题库分类失效（本次改动引入的回归）**
   分类原本只看 id 前缀（`ext-` → 扩展）；A02 之后扩展题主 id 变成 `ykb_/school_/kaoyan_` → 被误判成极光题 → **清空极光会把扩展题一起删掉**。
   改为查 `QGROUP`（分片加载时登记），未载入学科才退回前缀；清空/打开面板前先补载未载入学科。
