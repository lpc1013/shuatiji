## 2. P0 详解

### A01 · 强制登录门禁（fails-closed）— 与站点自我定位直接冲突

```js
// sync.js init()
if (token) { hideGate(); validateAndEnter(); }   // 有 token → pull
else { showGate(); }                              // 无 token → 直接弹门禁
// validateAndEnter(): pull 失败（断网/CloudBase 故障）→ clearAuth(); showGate()
```

后果：
1. **首次用户被挡**：只想刷题的人必须注册 CloudBase 账号。
2. **断网即踢出**：本地进度完好（localStorage），但 `body.gated` 遮罩锁死整页 → 离线无法学习。
3. **定位矛盾**：`app.js:845`「所有数据只存在这台设备的浏览器里」、`app.js:861`「刷题记 · 纯本地个人学习站」——文案承诺 local-first，行为是 cloud-mandatory。
4. **单点依赖**：云函数下线 = 站点整体不可用。
5. **换机/清缓存/分享给同学 = 卡死在登录页**。

**必修**：无 token / 网络失败时**不弹门禁**，正常进入学习；门禁降级为「用户主动点登录/需同步」时出现的账号卡。最小改动：`init()` 无 token 分支不再 `showGate()`；`validateAndEnter` 失败路径改 `hideGate()`。

> **修订（2026-09-13 用户指正）**：上句"门禁降级"措辞不准。门禁的用途是**跨设备数据通用**（手机刷、电脑续，进度经云端同步），纯个人自用反而最依赖它，故**门禁应当保留，而非降级或移除**。A01 的真实缺陷是"无 token 即全屏登录墙、缺本地降级出口"——断网/首开没网时本地进度完好却被锁死，且与 `app.js:845/861`「纯本地个人学习站」文案冲突。正确修法：**保留门禁 + 补未登录本地降级**（未登录静默走 localStorage；用户主动登录后一键合并上云）。第 5 条"换机/清缓存=卡死"在"跨设备同步"语境下改为：换机正是门禁要解决的场景（登录即拉回进度），但"清缓存/断网单设备离线"仍需本地降级兜底。第 183 行"A01 门禁降级"同样改为"A01 补本地降级出口"。

### A02 · ext id 内容寻址 → 孤儿进度（定时炸弹）

ext 题 id = `ext-<sha1(归一化题干)>`。任一题干编辑（错别字、措辞、选项值）→ hash 变 → 旧 `m1/m2/m3`、`qstat`、`wrong/fav/doubt` 全部指向不存在的旧键，**表现为"进度消失"且继续占 localStorage**。merged2 后续必然改题干 → 必然发生。极光题 id 为原始 UUID，不受影响。

**必修**：引入 ext id 别名映射（旧 hash→新 hash，或归一化题干→主 id），build 阶段做题干近似匹配回写；至少出具一次性迁移脚本。

### A03 · 同步 last-write-wins 静默丢标记

`reconcile` 按时间戳**整块覆盖**。多端各标记、或同设备重登后 pull → 本地被云端旧时间戳整包覆盖 → **一侧面学习标记静默丢失**，无逐字段合并、无冲突提示。对"每题掌握状态"这类标记型数据，等同于数据丢失。

**必修**：改为逐题/逐字段合并（以每题最近变更时间裁决，而非整包时间），或对 `wrong/fav/doubt/mastered/qstat` 做 field-level merge + 冲突提示。

### A04 · 限时考试无「下一题」

`app.js:1212-1214`：考试未交卷时只有「上一题 + 交卷」。桌面端答完一题只能开答题卡点题号（移动端靠左右滑动）——用户不会猜到要去答题卡翻页，这是核心流程残缺。

**必修**：考试未交卷时补「下一题」按钮，最后一题改禁用/提示交卷，与 `nextQ()` 边界逻辑对齐（防自动交卷与手动交卷双触发）。

## 4. 对抗性重点：137 项测试为什么全绿却漏了这些

这是全篇最有价值的部分——不是"测试不好"，而是**测试只覆盖它被要求覆盖的东西**。

| 盲区 | 根因 |
|---|---|
| 登录门禁 100% 未被测试 | `verify_jsdom.mjs:57` 只 eval `app.js / english.js / features.js`，**从不加载 `sync.js`**；真实页面 `index.html:54` 是加载它的 |
| 云依赖不可见 | 测试用磁盘 fetch shim（`verify_jsdom.mjs:37-49`），跨域请求直接返回 404 假响应 → 永远看不到"站点依赖一个云函数才能打开" |
| 所有"视觉"断言都是字符串匹配 | 断言的是"CSS 里有 `tabular-nums`"、"`78ch`"、"`min-height:44px`"这类**规则存在性**。jsdom 无布局引擎 → 网格空位、内容左对齐、canvas 模糊、暗色硬编码白块、hover 缺失天然不可测 |
| "SW 缓存名带版本"是假通过 | 断言只检查常量含 `shuati-` 前缀，语义（改版即失效）从未被验证；`CACHE` 实际写死 |
| 冒烟只点存在的按钮 | 41 次点击验证"存在的按钮点了不报错"——**缺失的按钮不会报错**，所以"考试无下一题"永远测不出来 |
| 数据断言不涉及体积 | `verify_site` 校验题数/字段/UUID，不校验 6.5MB explain 是否与 packs 一起被拉下 |
| 导入路径未被覆盖 | 无"导入旧备份 → 校验字段补齐"用例，B06 因此逃逸 |

**结论**：测试是回归网，不是发现网。建议补 3 类用例——① 加载 `sync.js` 并 mock 云失败，断言仍可进入学习；② 对每个视图断言"关键按钮集合存在"（防按钮丢失）；③ 导入旧格式快照，断言迁移后字段齐全。
